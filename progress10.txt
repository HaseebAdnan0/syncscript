## Iteration 1 - US-001: Create useVaultSocket hook
- Implemented WebSocket connection management hook at `frontend/src/hooks/useVaultSocket.ts`
- Files changed:
  - Created `frontend/src/hooks/useVaultSocket.ts`
  - Updated `PRD10.md` (marked US-001 complete)
- Learnings for future iterations:
  - Hook uses refs for WebSocket instance and event handlers to prevent unnecessary re-renders
  - Exponential backoff implemented with 1s, 2s, 4s, 8s... up to max 30s delay
  - Uses `isUnmountedRef` flag to prevent state updates after unmount
  - Event handlers stored in Map<string, Set<function>> for efficient multi-listener support
  - WebSocket URL constructed from `NEXT_PUBLIC_WS_URL` env var + `/vault/{vaultId}/`
  - Message format: `{ type: string, data: any }` for both send and receive
  - Typecheck passes without issues

## Iteration 3 - US-003: Create useRealtimeUpdates hook
- Implemented optimistic updates hook at `frontend/src/hooks/useRealtimeUpdates.ts`
- Files changed:
  - Created `frontend/src/hooks/useRealtimeUpdates.ts`
  - Updated `PRD10.md` (marked US-003 complete)
- Learnings for future iterations:
  - Hook integrates with useVaultSocket via `addEventListener` (not `on`/`off`)
  - Uses `send(eventType, data)` signature (two params, not object)
  - Accepts options with vaultId, queryKey, optional mutation, and success/error event names
  - Returns `optimisticUpdate` function that accepts variables and optional optimistic data
  - Tracks pending updates with unique IDs (timestamp + random) for reconciliation
  - On success event: invalidates TanStack Query cache to fetch fresh server state
  - On error event: rolls back to previous cached state using stored snapshot
  - Uses refs to track pending updates Map to prevent stale closures
  - Cleanup on unmount clears all pending updates
  - Typecheck passes without issues
