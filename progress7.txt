## Iteration 1 - US-001: Create Zustand auth store
- Created `frontend/src/stores/authStore.ts` with proper TypeScript types
- Files changed: frontend/src/stores/authStore.ts (new file)
- Learnings for future iterations:
  - Frontend is a git submodule - must commit changes inside frontend/ directory first
  - PRD specifies NO token storage (backend uses httpOnly cookies), NO persistence middleware
  - Store exports User interface and useAuthStore hook
  - Initial isLoading state is true (for auth check on app load)
  - setUser automatically derives isAuthenticated from user presence
---

## Iteration 2 - US-002: Create axios instance with interceptors
- Rewrote `frontend/src/lib/api.ts` to use httpOnly cookies instead of manual token handling
- Files changed: frontend/src/lib/api.ts (rewritten)
- Learnings for future iterations:
  - Critical: PRD specifies httpOnly cookies managed by backend, NOT client-side JWT tokens
  - Removed token-based auth logic (request interceptor with Bearer tokens, refresh token storage)
  - Added `withCredentials: true` to axios instance for cookie support
  - Response interceptor: on 401, POST to /auth/refresh/ (no body needed, cookies sent automatically)
  - On refresh failure, call clearUser() from auth store and redirect to /login
  - Kept ApiError and handleApiError utilities for consistent error handling
  - Request queueing mechanism prevents multiple simultaneous refresh attempts
---

## Iteration 3 - US-003: Create useAuth hook with auth operations
- Created `frontend/src/hooks/useAuth.ts` with login, register, logout, and refreshUser methods
- Files changed: frontend/src/hooks/useAuth.ts (new file)
- Learnings for future iterations:
  - All auth methods return `{ success, error }` for consistent UI error handling
  - login() accepts email and password parameters directly (not an object)
  - register() accepts RegisterData object with email, password, username, optional first_name/last_name
  - logout() clears local state even if API call fails (defensive programming)
  - refreshUser() is used for app initialization - clears user on failure (not authenticated)
  - All methods use useCallback with proper dependencies (setUser, clearUser, setLoading)
  - setLoading(true) at start, setLoading(false) in finally block for proper loading states
  - RegisterData interface exported for use in registration forms
