# Progress Log - PRD 17: User Dashboard & Analytics

## Learnings
(Patterns discovered during implementation)

- Annotation model has custom save() that calls full_clean() - use bulk_create() in tests to bypass validation
- Test database needs to be migrated before running tests (use --keepdb flag to preserve database)
- When testing with timestamps, use QuerySet.update() to bypass model validation
- Vault creation triggers signals that auto-create audit logs (vault.created + membership.added)
- Must clear AuditLog.objects.all().delete() after creating test vaults to isolate test data
- AuditLog has metadata JSONField for flexible action-specific data storage

## Iteration 4 - US-004: Create analytics endpoints
- Implemented three analytics endpoints for dashboard chart data
- Created GET /api/v1/dashboard/analytics/sources-timeline/
  - Returns sources added per day for last 30 days
  - Uses Django's TruncDate aggregation for efficient date grouping
  - Excludes deleted sources
  - Returns array: [{ date: "2026-02-01", count: 5 }, ...]
- Created GET /api/v1/dashboard/analytics/source-types/
  - Returns breakdown by source type with counts and percentages
  - Sorted by count (descending)
  - Percentages rounded to 1 decimal place
  - Returns array: [{ type: "PDF", count: 15, percentage: 45.5 }, ...]
- Created GET /api/v1/dashboard/analytics/top-collaborators/
  - Returns top 5 collaborators by contribution count
  - Counts sources created, annotations created, and audit log entries
  - Excludes current user from results
  - Shows user_id, name, avatar_url, and total contributions
  - Returns array sorted by contributions_count (descending)
- Files changed:
  - backend/apps/dashboard/views.py (added 3 analytics views, imported Count and TruncDate)
  - backend/apps/dashboard/urls.py (added 3 analytics routes)
  - backend/apps/dashboard/tests.py (added AnalyticsTests class with 15 comprehensive tests)
  - PRD17.md (marked US-004 complete)
- Learnings for future iterations:
  - TruncDate() from django.db.models.functions efficiently groups by date
  - Count() aggregation with values() creates grouped counts by field
  - Percentage calculation: (count / total * 100) with proper zero-handling
  - Contributions calculated from multiple sources: sources + annotations + audit logs
  - VaultMembership query gets all collaborators, then filter by contributions > 0
  - Top 5 selection done in Python after calculating all contributions
  - All endpoints scoped to accessible vaults (Q(owner=user) | Q(members=user))
  - All 15 analytics tests passing, total 29 dashboard tests passing

## Iteration 5 - US-005: Extend notifications app for dashboard
- Extended existing notifications app with dashboard-specific endpoints
- Added GET /api/v1/notifications/unread-count/ endpoint
  - Returns { count: N } for unread notifications (read_at IS NULL)
  - Filters by current user only
- Added POST /api/v1/notifications/{id}/mark-read/ endpoint
  - Marks single notification as read (idempotent)
  - Supports both POST and PATCH methods
  - URL changed from /read/ to /mark-read/ for consistency
- Added POST /api/v1/notifications/mark-all-read/ endpoint
  - Bulk updates all unread notifications for current user
  - Returns { updated: N } count of affected rows
  - Uses QuerySet.update() for efficiency
- Files changed:
  - backend/apps/notifications/views.py (added 2 new action methods to NotificationViewSet)
  - backend/apps/notifications/tests.py (added UnreadCountTestCase and MarkAllReadTestCase, updated URLs)
  - PRD17.md (marked US-005 complete)
- Learnings for future iterations:
  - Notification model already existed with needed fields (user, title, body, type, read_at, data, created_at)
  - Model has is_read property (computed from read_at IS NOT NULL)
  - Model has mark_as_read() method for individual notifications
  - ViewSet @action decorator with detail=False creates collection endpoints
  - ViewSet @action decorator with methods=['post', 'patch'] supports multiple HTTP methods
  - QuerySet.update() is efficient for bulk updates, bypasses model.save()
  - All 22 notification tests passing (list, filtering, ordering, mark-read, unread-count, mark-all-read)
