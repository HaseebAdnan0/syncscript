## Session Notes

### Implementation Order
The stories are ordered for dependency resolution:
1. US-001 to US-005: Backend services (app structure, lookups, citation engines)
2. US-006 to US-012: Backend API endpoints and caching
3. US-013 to US-014: Settings/preferences backend
4. US-015 to US-020: Frontend components
5. US-021 to US-022: Polish and enrichment

### Key Technical Decisions
- Hybrid sync/async: Structured citations sync, AI citations async via Celery
- Progressive batch export: Small (sync), Medium (cached+sync), Large (background job)
- Rate limiting: 50/user/day, 200/vault/day for AI citations
- Caching: Citations stored in source.metadata.citations JSON
- Settings hierarchy: Vault override > User preference > None

## Iteration 4 - US-004: Implement citeproc-py structured citation service
- Created apps/citations/services/structured_citation.py with comprehensive citation generation
- Implemented has_complete_metadata() function:
  - Validates presence of title, authors, and date (minimum required fields)
  - Accepts flexible field names (author/authors, date/publication_date/year)
  - Returns boolean indicating if metadata is complete enough for citation
- Implemented generate_structured_citation() function:
  - Supports all 6 citation formats (APA7, MLA9, CHICAGO17, BIBTEX, IEEE, HARVARD)
  - Uses citeproc-py library for CSL-based formats (APA, MLA, Chicago, IEEE, Harvard)
  - Manual BibTeX generation (not CSL-based) with proper entry types
- Implemented _convert_to_csl_json() helper:
  - Converts metadata dict to CSL JSON format
  - Parses author names ("Last, First" or "First Last" format)
  - Extracts year from publication date with regex
  - Determines source type (article-journal, book, webpage) based on metadata fields
- Implemented _get_style_file() helper:
  - Maps CitationFormat enum to CSL style file names
  - Tries citeproc-py-styles package first (bundled styles)
  - Fallback to local apps/citations/styles/ directory
  - Raises FileNotFoundError if style not found
- Implemented _generate_bibtex() helper:
  - Manual BibTeX generation for @article, @book, @misc entry types
  - Proper field mapping (journal, volume, number, pages, publisher, edition, isbn, doi, url)
  - No trailing comma on last field
- Added citeproc-py>=0.6.0 and citeproc-py-styles>=0.1.3 to requirements.txt
- Added 19 comprehensive unit tests:
  - 8 tests for has_complete_metadata() with various edge cases
  - 3 tests for BibTeX generation (article, book, web source)
  - 5 tests for CSL format generation (APA, MLA, Chicago, IEEE, Harvard) with mocking
  - 3 tests for error cases and edge cases (incomplete metadata, DOI, URL)
- Tests: All 19 tests pass
- Typecheck: Passes with 0 errors (fixed with Dict[str, Any] type annotation and type: ignore for formatter)
- Files changed: backend/apps/citations/services/structured_citation.py (360 lines), backend/apps/citations/tests.py (+300 lines), backend/requirements.txt
- Committed: b991609

Learnings for future iterations:
- citeproc-py uses CSL (Citation Style Language) for formatting
- CSL JSON format requires specific structure: {'id', 'type', 'title', 'author': [{'family', 'given'}], 'issued': {'date-parts': [[year]]}}
- citeproc-py-styles package provides bundled CSL style files (no need to download separately)
- BibTeX is not CSL-based and needs manual generation
- BibTeX entry types: @article (journals), @book (books), @misc (web sources, general)
- Pyright requires explicit type annotations for dict values that can be mixed types (use Dict[str, Any])
- Mocking citeproc library requires mocking _get_style_file() function, not get_style_filepath()
- Author name parsing: support both "Last, First" and "First Last" formats
- Date extraction: use regex to find 4-digit year in publication_date strings
- Source type detection: journal → article-journal, isbn/publisher → book, url without journal → webpage

## Iteration 5 - US-005: Implement Claude AI citation service
- Created apps/citations/services/ai_citation.py with comprehensive AI-powered citation generation
- Implemented generate_ai_citation() function:

  - Uses Claude 3.5 Sonnet model for accuracy
  - Validates ANTHROPIC_API_KEY environment variable
  - Handles API errors gracefully
- Implemented _build_system_prompt() helper:
  - Format-specific citation rules for all 6 formats (APA7, MLA9, CHICAGO17, BIBTEX, IEEE, HARVARD)
  - Detailed examples of correct citations for each format
  - Missing field handling rules (n.d., Unknown, Anonymous)
  - Italicization rules (journals, books) for HTML version
  - Instructs Claude to return TWO versions separated by "---SPLIT---"

  - Includes all fields: title, url, authors, journal, volume, issue, pages, publisher, doi, isbn
  - Shows "Not provided" for missing fields so Claude can handle gracefully
- Implemented _parse_response() helper:
  - Splits response on "---SPLIT---" separator
  - Fallback to same content if separator not found
  - Returns tuple of (plain_text, html)
- Added 12 comprehensive unit tests:
  - 2 tests for response parsing (with/without separator)
  - 3 tests for system prompt building (APA7, MLA9, BibTeX)
  - 3 tests for user prompt building (complete metadata, incomplete metadata, authors as string)
  - 2 tests for full citation generation with mocked Claude API (APA7, BibTeX)
  - 1 test for missing API key error
  - 1 test for incomplete metadata handling
- Tests: All 12 tests pass
- Typecheck: Passes with 0 errors (used type: ignore for Anthropic SDK ContentBlock typing)
- anthropic SDK already present in requirements.txt (>=0.40.0)
- Files changed: backend/apps/citations/services/ai_citation.py (353 lines), backend/apps/citations/tests.py (+194 lines)
- Committed: b90ef6a

Learnings for future iterations:
- Claude API uses Anthropic SDK with client.messages.create()
- Model: claude-3-5-sonnet-20241022 is most accurate for academic citations
- System prompt should include:
  - Format rules with specific examples
  - Punctuation and spacing rules
  - Missing field handling conventions
  - "---SPLIT---" instruction for plain text and HTML versions
- User prompt should list all available metadata fields with "Not provided" for missing ones
- Response parsing needs fallback if Claude doesn't include separator
- Each citation format has different conventions:
  - APA7: Author, A. A. (Year). Title. Journal, volume(issue), pages.
  - MLA9: Author. "Article Title." Journal, vol. X, no. Y, Year, pp. Z-ZZ.
  - Chicago17: Author. Year. "Article Title." Journal volume (issue): pages.
  - BibTeX: @entry{key, author={...}, title={...}, ...}
  - IEEE: F. I. Lastname, "Article title," Journal, vol. X, no. Y, pp. Z-ZZ, Year.
  - Harvard: Author, F.I., Year. 'Article title', Journal, volume(issue), pp. pages.
- HTML version uses <i> tags for italics (journals, books)
- Plain text version has no HTML tags
- Access date for web sources: datetime.now().strftime("%B %d, %Y")
- Anthropic SDK ContentBlock typing is complex, use type: ignore for .text attribute

## Iteration 6 - US-006: Create citation generation endpoint
- Created POST /api/v1/citations/sources/{id}/citation/ endpoint
- Implemented CitationViewSet with generate_citation action
- Request serializer: CitationRequestSerializer validates format enum (apa7, mla9, chicago17, bibtex, ieee, harvard)
- Response serializer: CitationResponseSerializer with citation, citation_html, format, source, cached fields
- Endpoint logic:
  - Validates user has vault permission (viewer+)
  - Checks cache first (source.metadata.citations[format])
  - Determines generation method: structured (complete metadata) or AI (incomplete)
  - Structured: uses citeproc-py synchronously
  - AI: uses Claude API synchronously (async in US-008)
  - Caches generated citation in source.metadata
- URL routing: /api/v1/citations/sources/{id}/citation/ via DRF router
- Created 8 comprehensive endpoint tests:
  - test_generate_citation_structured: complete metadata, BibTeX format
  - test_generate_citation_ai: incomplete metadata, APA7 format with mocked Claude
  - test_generate_citation_caching: verify cache hit on second request
  - test_generate_citation_unauthenticated: 401 error
  - test_generate_citation_no_permission: 403 error for non-member
  - test_generate_citation_invalid_format: 400 error for invalid format
  - test_generate_citation_source_not_found: 404 error
  - test_generate_citation_with_vault_member: viewer role can generate citations
- All 8 tests pass
- Typecheck passes with 0 errors (added type: ignore for ChoiceField assignment)
- Files changed: backend/apps/citations/views.py (156 lines), backend/apps/citations/serializers.py (33 lines), backend/apps/citations/urls.py (12 lines), backend/apps/citations/tests.py (+212 lines)
- Committed: 5baadc4

Learnings for future iterations:
- Citation format comes from serializer as string, must convert to CitationFormat enum before passing to services
- Cache key is the string format value (e.g., 'apa7'), not the enum
- User creation in tests requires username parameter: User.objects.create_user(email, username, password)
- DRF ChoiceField with list of tuples causes pyright error, use type: ignore[assignment]
- Vault permission checking pattern: check owner first, then membership with required roles
- Citation caching structure: source.metadata['citations'][format] = {text, html, generated_at, source}
- Custom action with URL parameter: @action(detail=False, url_path=r'sources/(?P<source_id>\d+)/citation')
- REST framework test client: force_authenticate(user) for authenticated requests
- Django test database: use --keepdb flag to preserve test database between runs
