## Session Notes

### Implementation Order
The stories are ordered for dependency resolution:
1. US-001 to US-005: Backend services (app structure, lookups, citation engines)
2. US-006 to US-012: Backend API endpoints and caching
3. US-013 to US-014: Settings/preferences backend
4. US-015 to US-020: Frontend components
5. US-021 to US-022: Polish and enrichment

### Key Technical Decisions
- Hybrid sync/async: Structured citations sync, AI citations async via Celery
- Progressive batch export: Small (sync), Medium (cached+sync), Large (background job)
- Rate limiting: 50/user/day, 200/vault/day for AI citations
- Caching: Citations stored in source.metadata.citations JSON
- Settings hierarchy: Vault override > User preference > None

Learnings for future iterations:
- Celery task decorators: `@shared_task(bind=True, max_retries=2, default_retry_delay=30, time_limit=30)`
- `bind=True` gives access to `self.retry()` for retry logic
- `time_limit` enforces hard timeout (30s as per requirements)
- Celery `.delay()` returns AsyncResult with `.id` property for task tracking
- AsyncResult states: PENDING, SUCCESS, FAILURE, RETRY, STARTED
- Task status endpoint uses `AsyncResult(task_id)` from `celery.result`
- DRF @action with custom URL pattern: `url_path=r'tasks/(?P<task_id>[a-f0-9\-]+)'`
- Celery task IDs are UUIDs, must use UUID pattern in tests
- When changing API behavior (sync to async), must update all existing tests
- Progressive approach: structured citations stay sync, only AI citations go async
- Task caching helper can be shared between view and task (_cache_citation utility)
- Pyright needs `type: ignore[misc]` for Celery `.delay()` call
- Task error handling: `raise self.retry(exc=exc)` for automatic retry with exponential backoff
- HTTP 202 Accepted: standard status for accepted async operations
- Return task_id and status_url in 202 response for client polling
