## Implementation Notes

### Decisions Made
- Using django-allauth (full-featured with social adapters)
- Password confirmation required for linking OAuth to existing accounts
- At least one auth method required (prevent lockout)
- Prompt for email when GitHub email is private
- Redirect-based OAuth flow (not popup)

## Iteration 2 - US-002: Configure Google OAuth provider settings
- Added SOCIALACCOUNT_PROVIDERS configuration for Google OAuth 2.0
- Configured required scopes: 'email' and 'profile'
- Added GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET environment variables to .env.example
- Set callback URL pattern to `/api/v1/auth/google/callback/`
- Documented complete Google Cloud Console setup in USER_SETUP.md (with step-by-step instructions)
- Typecheck passed (django-allauth deprecation warnings are expected)

Files changed:
  - backend/config/settings.py (added SOCIALACCOUNT_PROVIDERS config)
  - backend/.env.example (added Google OAuth env vars)
  - .planning/USER_SETUP.md (added Google OAuth setup section)

Learnings for future iterations:
  - Google OAuth setup requires 6 main steps: create project, enable API, configure consent screen, create credentials, add redirect URIs, and save credentials
  - Callback URL must match exactly what's configured in Google Cloud Console
  - For testing, OAuth consent screen should be in "Testing" mode with test users added
  - SOCIALACCOUNT_PROVIDERS uses nested 'APP' config with 'client_id' and 'secret' keys
  - Environment variables should have sensible defaults (empty string) to avoid crashes when not configured

- Added GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET environment variables to .env.example
- Set callback URL pattern to `/api/v1/auth/github/callback/`
- Documented complete GitHub OAuth App setup in USER_SETUP.md (with step-by-step instructions)
- Typecheck passed (no new errors introduced)

Files changed:
  - backend/config/settings.py (added GitHub to SOCIALACCOUNT_PROVIDERS)
  - backend/.env.example (added GitHub OAuth env vars)
  - .planning/USER_SETUP.md (added GitHub OAuth setup section)

Learnings for future iterations:
  - GitHub OAuth setup is simpler than Google (no API enablement required)
  - GitHub OAuth Apps are created directly from Developer Settings
  - GitHub's 'user:email' scope is needed to access private emails
  - Pattern is consistent: each provider added to SOCIALACCOUNT_PROVIDERS dict with APP and SCOPE keys
  - Can have separate OAuth Apps for dev/prod or use same with multiple callback URLs

## Iteration 4 - US-004: Create custom OAuth adapter for JWT integration
- Created apps/users/adapters.py with JWTSocialAccountAdapter
- Extended DefaultSocialAccountAdapter from django-allauth
- Overrode get_login_redirect_url() to generate JWT tokens after successful OAuth
- Used RefreshToken.for_user() from simplejwt (same pattern as CustomTokenObtainPairView)
- Set both access_token and refresh_token in httpOnly cookies with proper settings
- Configured redirect to frontend callback page: /auth/callback?success=true
- Added authentication_error() method to handle OAuth failures gracefully
- Configured SOCIALACCOUNT_ADAPTER in settings.py
- Verified adapter imports successfully via Django shell
- Typecheck passed with mypy --ignore-missing-imports --check-untyped-defs

Files changed:
  - backend/apps/users/adapters.py (created)
  - backend/config/settings.py (added SOCIALACCOUNT_ADAPTER setting)

Learnings for future iterations:
  - django-allauth adapters use get_login_redirect_url() not authentication_success_response()
  - HttpResponseRedirect can set cookies before returning to client
  - Cookie settings must match production requirements: httponly=True, secure=(not DEBUG), samesite='Lax'
  - Token lifetimes for cookies should match SIMPLE_JWT settings (15min access, 7day refresh)
  - Use noqa: ARG002 to suppress unused parameter warnings for required method signatures
  - Testing OAuth adapters requires Django shell context, not raw Python imports
