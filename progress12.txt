## Iteration 6 - US-006: Create Google OAuth callback handler
- Enhanced JWTSocialAccountAdapter in apps/users/adapters.py with account linking logic
- Implemented pre_social_login() to detect existing accounts and handle linking scenarios
- OAuth callback handled automatically by allauth (via /api/v1/auth/accounts/google/login/callback/)
- Adapter logic:
  - If email exists with OAuth already linked: proceed with login, generate JWT
  - If email exists with password only: store OAuth data in session, redirect with link_required=true
  - If email is new: let allauth auto-create user, generate JWT, redirect with success=true
  - If no email provided (GitHub private): store data in session, redirect with email_required=true
- Used ImmediateHttpResponse exception to abort allauth flow when linking/email required
- Added allauth.urls to config/urls.py for OAuth callback routing
- JWT tokens set in httpOnly cookies on successful login
- Typecheck passes (pre-existing model errors not related to OAuth)

Files changed:
  - backend/apps/users/adapters.py (enhanced pre_social_login and get_login_redirect_url)
  - backend/config/urls.py (added allauth.urls for OAuth callbacks)
  - PRD12.md (marked US-006 complete)

Learnings for future iterations:
  - allauth handles OAuth callbacks automatically at /accounts/{provider}/login/callback/
  - Use ImmediateHttpResponse exception to abort allauth flow and redirect early
  - pre_social_login() is called BEFORE user creation, perfect for account linking checks
  - get_login_redirect_url() is called AFTER successful auth, perfect for JWT generation
  - Session storage appropriate for temporary OAuth data during linking flow
  - sociallogin.is_existing checks if SocialAccount already exists (not if email exists)
  - SOCIALACCOUNT_AUTO_SIGNUP=True makes allauth create users automatically when email is new

## Iteration 12 - US-012: Create OAuth provider unlink endpoint
- Created DisconnectOAuthProviderView in apps/users/views.py
- Implemented DELETE /api/v1/auth/oauth/connected/{provider}/ endpoint
- Validates provider is 'google' or 'github', returns 400 for invalid providers
- Checks if SocialAccount exists for user, returns 404 if not found
- Prevents account lockout by checking for alternative auth methods:
  - User must have either a usable password (has_usable_password()), OR
  - At least one other OAuth provider connected
- Returns 400 error with helpful message if attempting to remove only auth method
- Deletes SocialAccount on success and returns 204 No Content
- Added DisconnectOAuthProviderView to urls.py imports
- Configured URL routing: auth/oauth/connected/<str:provider>/
- Django check passes (expected deprecation warnings)
- Import and URL reverse tests pass
- Committed successfully

  - backend/apps/users/urls.py (added import and route)
  - PRD12.md (marked US-012 complete)

Learnings for future iterations:
  - Use has_usable_password() to check if user has password authentication set up
  - has_usable_password() returns False for OAuth-only users (password set to unusable)
  - SocialAccount.objects.filter().exclude() can count other providers efficiently
